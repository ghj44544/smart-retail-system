# 智能零售用户行为分析系统 - 前端项目开发文档

> **项目名称**: 智能零售用户行为分析系统  
> **前端技术栈**: Vue3 + Vite + TypeScript + Element Plus + ECharts + Pinia  
> **后端技术栈**: Python FastAPI + MySQL + Redis  
> **文档版本**: v1.0  
> **生成日期**: 2026-05-28

---

## 一、项目概述

智能零售用户行为分析系统是一个面向零售行业的数据分析平台，提供数据驾驶舱大屏、RFM 用户价值分析、K-Means 聚类分群、商品管理、订单追踪、行为转化漏斗、智能推荐等核心功能。

前端采用 Vue3 + TypeScript 构建，使用 Element Plus 组件库和 ECharts 图表库，通过 Pinia 管理全局状态，Vue Router 实现页面路由和权限守卫。所有 API 接口预留了后端对接通道，当前使用 Mock 数据独立运行。

## 四、核心架构详解

### 4.1 应用入口 (main.ts)

```typescript
// 1. 创建 Pinia + 持久化插件（自动同步 localStorage）
const pinia = createPinia()
pinia.use(piniaPluginPersistedstate)

// 2. 创建 Vue 应用
const app = createApp(App)

// 3. 注册 Pinia → Router
app.use(pinia).use(router)

// 4. 挂载
app.mount('#app')
```

### 4.2 HTTP 请求封装 (utils/request.ts)

基于 Axios 实例，挂载两个拦截器：

**请求拦截器**：从 `localStorage` 读取 `access_token`，自动添加到请求头 `Authorization: Bearer <token>`。

**响应拦截器**：
- `code !== 200` → ElMessage 弹窗错误提示
- HTTP `401` → 清除 Token，跳转到 `/login`
- HTTP `403` → 提示"无权限"
- HTTP `500` → 提示"服务器错误"

### 4.3 认证状态管理 (stores/auth.ts)

使用 Pinia + `pinia-plugin-persistedstate` 实现：

| Action | 功能 | API |
|--------|------|-----|
| `login(params)` | 登录 → 保存 Token + 用户信息 | POST /auth/login |
| `fetchUserInfo()` | 刷新时恢复用户状态 | GET /auth/me |
| `logout()` | 登出 → 清除状态 → 跳转登录 | POST /auth/logout |
| `clearAuth()` | 清除 Token 和用户信息 | 内部方法 |

**持久化**：`token` 和 `userInfo` 自动同步到 `localStorage`，页面刷新不丢失登录状态。

### 4.4 路由守卫 (router/index.ts)

全局前置守卫 `beforeEach` 逻辑：

1. 目标页需要登录 (`meta.requiresAuth=true`) 且未登录 → 重定向 `/login?redirect=原路径`
2. 已登录访问 `/login` → 重定向 `/dashboard`
3. 设置浏览器标签标题

### 4.5 主布局 (layouts/MainLayout.vue)

### 5.1 登录/权限模块

**文件**: `src/views/login/index.vue`

**路由**: `/login`

**API 接口**:

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 登录 | POST | `/auth/login` | 提交 username/password → 返回 JWT Token + UserInfo |

- 背景底板使用 `denglu.png` 图片铺满

- 卡通樱花五瓣花自定义光标（带小脸 + 绿叶 + 茎）
- 毛玻璃半透明登录卡片
- 左侧品牌展示区 → 蓝粉渐变标题 + 描述文字
- 登录成功自动跳转到 redirect 目标页或 `/dashboard`

**Mock 模式**: 任意非空用户名+密码均可登录，使用预设账户则显示预设昵称。

## 九、Mock 数据说明

所有 API 文件均使用 `USE_MOCK = true` 开关控制数据来源：

```typescript
const USE_MOCK = true  // Mock 模式 → 前端独立运行
const USE_MOCK = false // 真实模式 → 请求后端接口
```

后端就绪后，只需将各 API 文件中的 `USE_MOCK` 改为 `false`，即可无缝切换到真实后端。此外需要确保：

1. 后端运行在 `http://localhost:8000`
2. API 基础路径为 `/api/v1`
3. 响应格式为 `{ code: 200, message: "success", data: {...} }`
4. JWT Token 通过 `Authorization: Bearer <token>` 请求头传递

Vite 已配置代理：`/api` 请求自动转发到 `http://localhost:8000`。
